How it was run

  1. evals/db-cli/run.py builds two throwaway arms from git archive HEAD: with keeps .claude/skills/db-cli, without deletes it and the hint to it in .mcp.json. Both lose evals/ (the expected answers live there) and become fresh one-commit repos, so the agent can't git show the skill back.
  2. Every run is a fresh claude -p in one arm: --setting-sources project, no MCP server at all (--strict-mcp-config with an empty config), bypassPermissions, no session persistence, a $3 budget cap, and the parent's CLAUDE* env vars stripped. The shell is the only way into the local Postgres.
  3. Jobs are interleaved (run i of every task, both arms, then run i+1), 6 in parallel. Each writes a stream-json log.
  4. report.py grades each final answer with the regexes in tasks.json (all expected facts present, trap absent), reads tokens, cost and duration from the result event, and classifies the route from the Bash commands. pretty_report.py renders this page from the same parsing.
evals/db-cli/run.py --out $OUT                 # defaults: --runs 7 --model sonnet --parallel 6
evals/db-cli/report.py $OUT --html $OUT/report.html  # the plain tables
evals/db-cli/pretty_report.py $OUT --commit $(git rev-parse --short HEAD)   # this page + db-cli-runs.json
evals/db-cli/pretty_report.py docs/eval/db-cli-runs.json                   # rebuild it without the logs
